# Інструкція власника: ключ, копії бібліотеки, тестувальники, збірки

Стан на 2026-09-06 (ADR-0019). Усе, що тут описано, виконується на
власному ПК власника; Docker Desktop має бути запущений, бо інструменти
Rust на цьому ПК працюють лише в контейнері.

Короткий покроковий сценарій «як підключити тестувальника» — окремим
файлом: `TESTER_ONBOARDING.uk.md`.

## 1. Ключ видачі

- Файл: `C:\Users\<you>\.jlr-scanner\library-issuer.key`, один рядок із
  64 символів. Резервна копія на флешці зроблена 2026-09-06.
- Ніколи: в репозиторій, у чат, у пошту, у спільну хмару. У застосунку
  лежить лише публічна половина ключа (id `382146ce`), нею він перевіряє
  підпис на штампі; без приватної половини дійсної копії не зробити.
- Якщо ключ загублено: зробити новий командою нижче, публічну половину
  додати до списку `TRUSTED_ISSUER_KEYS` у
  `crates/diagnostic-session/src/issue.rs`, зібрати застосунок і видати
  всі копії заново. Старі копії доживуть до своєї дати.

```bash
docker run --rm -v "C:/Users/<you>/Desktop/jlr-scanner:/w" -w /w -v jlr-cargo-registry:/usr/local/cargo/registry -v "C:/Users/<you>/.jlr-scanner:/issuer" rust:1.98-slim sh -c 'cargo run --release -q -p diagnostic-session --example stamp_library -- --new-key /issuer/library-issuer-2.key'
```

## 2. Видати копію тестувальнику

Одна команда з кореня репозиторію:

```bash
powershell -File scripts/stamp-library.ps1 -IssuedTo "Ім'я Прізвище"
```

Що вона робить: бере бібліотеку з `Downloads\prowlone-library`,
пише копію в `Downloads\prowlone-issued\<ім'я>`, ставить штамп на 30
днів із підписом, читає копію так, як прочитає застосунок, і лише тоді
пакує в `Downloads\prowlone-issued\prowlone-library-<ім'я>.zip`.
Якщо перевірка не пройшла, команда зупиняється і zip не створюється.

- Інший термін: `-Days 60`. Собі: `-IssuedTo "Oleg" -Days 365` (уже
  видано до 2027-09-06, код `5050-F8EF`, папка `prowlone-issued\Oleg`).
- Тестувальнику надіслати три речі, одним каналом на одну людину:
  1. zip його копії;
  2. інсталятор потрібної системи з останньої збірки
     (`Downloads\jlr-scanner-build-<sha>\`), хеш є в `CURRENT_STATE.md`;
  3. `docs/TESTER_GUIDE.uk.md` або `docs/TESTER_GUIDE.md`.
- Записати: кому, коли, код копії, до якої дати. Код видно у файлі
  `issued_to.json` копії і в кожному звіті, який тестувальник надішле.

## 3. Продовжити або перевірити копію

- Продовжити означає видати знову тією самою командою: буде новий код і
  нова дата. Стара копія працює до своєї дати, далі застосунок її
  відхиляє і просить нову; за тиждень до дати він попереджає сам.
- Перевірити будь-яку папку так, як це зробить застосунок:

```bash
docker run --rm -v "C:/Users/<you>/Desktop/jlr-scanner:/w" -w /w -v jlr-cargo-registry:/usr/local/cargo/registry -v "C:/Users/<you>/Downloads:/downloads" rust:1.98-slim sh -c 'cargo run --release -q -p diagnostic-session --example stamp_library -- --check "/downloads/prowlone-issued/Ім_я"'
```

Відповідь `state: Loaded` і `issue: Matches` означає, що копія дійсна.

## 4. Що робити зі звітами тестувальників

Тестувальник надсилає файл звіту сесії, файл захоплення і кілька рядків
про авто. Звіт перетворюється на захоплений маніфест бібліотеки:

```bash
docker run --rm -v "C:/Users/<you>/Desktop/jlr-scanner:/w" -w /w -v jlr-cargo-registry:/usr/local/cargo/registry -v "C:/Users/<you>/Downloads:/downloads" rust:1.98-slim sh -c 'cargo run --release -q -p report-intake --example intake -- /downloads/reports/report.json /downloads/prowlone-library'
```

Результат `captured-<id>.json` лягає в папку бібліотеки. Наступні копії
вже несуть його, і в огляді автомобіля підтверджені модулі показуються як
`CAPTURE_VALIDATED`. Це і є накопичення нашої власної, виміряної бази.

## 5. Збірки

- Номер збірки: 0.9.N, де N це число, яке називають тестувальники, і воно росте лише коли збірку роздають. Підняти номер перед такою збіркою:

```bash
node scripts/bump-version.mjs 0.9.2
```

  Скрипт міняє всі п'ять файлів, де живе версія, і друкує команди коміту й тегу. Коміт `release: 0.9.2`, тег `v0.9.2`, пуш із тегами. Ім'я інсталятора і образу Tauri бере з версії сама.
- Версія й коміт видно внизу застосунку, наприклад `0.9.1 · a1b2c3d`, і в кожному звіті сесії як `application_version` та `application_build`. Тестувальник називає це число, коли пише про проблему.

- Кожен пуш у гілку запускає CI; збірка macOS тарифікується вдесятеро.
  Пуші, що торкаються лише документів, збірку не запускають.
- Якщо GitHub пише, що джоби не стартували через оплату: Settings →
  Billing and plans, підняти spending limit або дочекатися нового місяця.
  Після цього збірку перезапускає `gh run rerun <id>` без нового коміту.
- Готові інсталятори: від 0.9.3 у `Downloads\prowlone-build-<версія>\`, 0.9.1 і 0.9.2 у `Downloads\jlr-scanner-build-<версія>\`, раніше за хешем коміту; хеші файлів записані в `CURRENT_STATE.md`.
- Пуш тегу `v…` запускав збірку вдруге; з 0.9.1 workflow збирає лише гілки, тег збірки не запускає.
- Перша збірка після `b3fa55d` приймає лише штамповані копії: стару
  папку `prowlone-library` вона відхилить, бери копію з
  `prowlone-issued\Oleg`.

## 6. Якщо щось не так

- «Термін копії минув» у тестувальника: видати знову, розділ 2.
- «У цій папці немає штампа видачі»: це папка-джерело без штампа, треба
  дати копію.
- Копію змінили або переслали з іншого ПК зі зміненими файлами: застосунок
  каже «дані не збігаються зі штампом», видати знову.
- Загублений ключ: розділ 1.

## 7. Стенд (віртуальне авто)

- Кнопка «Підʼєднати стенд (віртуальне авто)» в панелі адаптера. Адаптер
  і авто не потрібні: віртуальне авто збирається з завантаженої бібліотеки
  для тієї програми й модельного року, що обрано в сесії, і відповідає
  на ті самі команди, що йдуть у живе авто.
- **Сценарій** — число поруч із кнопкою. `0` — справне авто: модулі
  відповідають, жодного коду помилки немає. Будь-яке інше число дає кожному
  модулю нуль, один або два коди, узяті з тих, що бібліотека описує саме для
  цього модуля, тож у кожного показаного коду є розшифровка. Одне число
  завжди дає ту саму картину, різні числа — різні; число видно у смузі
  «СТЕНД» і в звіті сесії (`bench_scenario`), тож той самий екран можна
  відтворити за звітом.
- Поки стенд підʼєднано, все вікно помаранчево-пісочне, зі смугою
  «СТЕНД · віртуальне авто · дані синтетичні» вгорі й унизу. Знімок екрана
  зі стенда не сплутати з авто.
- Нічого зі стендової сесії не зберігається: кнопки збереження вимкнені,
  звіт показується лише на екрані, а команда запису в оболонці відмовляє
  сама. Якби стендовий файл і зʼявився, він позначений `session_mode:
  bench`, і приймання звітів його відхиляє.
- Сесія або стендова, або справжня. Якщо в сесії вже є записи, перед
  перемиканням програма просить почати нову сесію.
- Для чого: показати програму людині без авто, дати тестувальнику пройти
  всі кроки до живого авто, повторити крок, що не вдався в авто, і
  відрізнити помилку програми від мовчання авто. Доказом стенд не є
  ніколи.

## 8. Назва застосунку

- Від 0.9.3 продукт називається ProwlOne (`ADR-0021`). Стара назва несла
  марку JLR у собі, і перед публічним виходом її треба було зняти.
- Ідентифікатор застосунку теж змінився, тому нова збірка ставиться поруч
  зі старою, а не поверх. Стару («JLR Scanner») прибрати через
  «Установлені програми», а якщо Smart App Control блокує деінсталятор,
  то руками, розділ 9.
- Копії бібліотеки, видані під старою назвою, працюють до своєї дати:
  штамп перевіряється за іменем, записаним усередині самого файла.
  Нові копії підписуються як ProwlOne.
- Файли звітів тепер називаються `prowlone-...json` замість
  `jlr-scanner-...json`. Приймання звітів приймає і старі, і нові.

## 9. Windows 11 зі Smart App Control: що робити

Перевірено 2026-09-09 на власному столі власника, двічі за день. Smart
App Control блокує непідписані файли, і кожна нова збірка для нього новий
файл, тож кожна стартує заблокованою. Винятку для окремої програми немає.
Вимкнути його можна в «Безпека Windows» → «Керування програмами та
браузером» → «Параметри Smart App Control», і з квітня 2026 там само
ввімкнути назад. Антивірус при цьому лишається увімкненим — вимикається
саме Smart App Control, не захист у реальному часі.

Стан читається в реєстрі: `VerifiedAndReputablePolicyState` у
`HKLM:\SYSTEM\CurrentControlSet\Control\CI\Policy` — `0` вимкнений,
`1` блокує, `2` спостерігає. 9 вересня значення збіглося з поведінкою в
обидва боки, тож орієнтуватися на нього можна:

```powershell
(Get-ItemProperty 'HKLM:\SYSTEM\CurrentControlSet\Control\CI\Policy').VerifiedAndReputablePolicyState
```

**Він повертається сам.** Того ж дня 0.9.4 стала о 9:43, коли він був
вимкнений; о 10:28 і 10:37 політики Code Integrity оновилися і політика
`{0283ac0f-fff1-49ae-ada1-8a933130cad6}` знову активувалася; о 13:55
наступна збірка вже була заблокована при подвійному кліку. Тому перед
установкою дивись значення, а не пам'ять про те, що вимикав уранці.

**«Розблокувати» у властивостях файлу може не бути, і це не поламка.**
Кнопка з'являється лише в файла з міткою `Zone.Identifier`, яку ставить
браузер. Інсталятор, завантажений через `gh` чи `curl`, її не має, тож і
кнопки немає — перевірити можна так:

```powershell
Get-Item "$env:USERPROFILE\Downloads\prowlone-build-0.9.5\ProwlOne_0.9.5_x64-setup.exe" -Stream *
```

Якщо в списку лише `:$DATA`, мітки немає. Головне: мітка стосується
SmartScreen, а блокує Smart App Control — це різні речі, і зняття мітки
його не вгамує.

- **Установка впирається в «Already Installed» або «Unable to uninstall».**
  Інсталятор хоче спершу запустити старий деінсталятор, а той
  заблокований. Обхід: тиха установка, вона не показує цих сторінок.
  У PowerShell:

```powershell
& "$env:USERPROFILE\Downloads\prowlone-build-0.9.5\ProwlOne_0.9.5_x64-setup.exe" /S
```

- **Видалити програму не виходить.** Деінсталятор непідписаний, тому
  заблокований так само. Ручне видалення, це рівно те, що робиться
  деінсталятором, і нічого більше:

```powershell
Stop-Process -Name prowlone-shell -ErrorAction SilentlyContinue
Remove-Item -LiteralPath "$env:LOCALAPPDATA\ProwlOne" -Recurse -Force
Remove-Item -LiteralPath "$env:USERPROFILE\Desktop\ProwlOne.lnk" -Force
Remove-Item -LiteralPath "$env:APPDATA\Microsoft\Windows\Start Menu\Programs\ProwlOne.lnk" -Force
Remove-Item -LiteralPath "HKCU:\Software\Microsoft\Windows\CurrentVersion\Uninstall\ProwlOne" -Recurse -Force
Remove-Item -LiteralPath "HKCU:\Software\prowlone" -Recurse -Force
```

  Останній ключ обов'язковий: саме він каже інсталятору «програма вже
  стоїть». Для старої назви ті самі рядки з `JLR Scanner` замість
  `ProwlOne` і `jlrscanner` замість `prowlone`.
- **Значок ярлика порожній або чужий.** Це кеш значків Windows, а не
  програма; сам знак лежить у файлі. `ie4uinit.exe -show`, або F5 на
  робочому столі, або перезаходження в систему.
- **Менше збірок.** Кожна збірка на такій машині проходить усе це
  знову. Зміни збирати в одну збірку, а не робити по збірці на дрібницю.
- **Для тестувальників** цей шлях не годиться. Підпис відкладено
  9 вересня 2026 разом із безкоштовним шляхом: SignPath забороняє закриті
  компоненти від автора проєкту, а видана бібліотека це саме він, та й
  сертифікат не вгамовує SmartScreen, доки не набрано репутацію
  завантаженнями (`F3_1_WINDOWS_SIGNING.md`). Отже Windows-збірку давати
  тим, у кого Windows 10 або вимкнений Smart App Control, і чесно писати
  про це в оголошенні.
