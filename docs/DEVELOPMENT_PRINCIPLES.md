# Development Principles

1. No coding for coding's sake.
2. Every feature closes a defined product capability or research uncertainty.
3. Physical facts beat assumptions.
4. Unknown stays `UNKNOWN`.
5. Do not generalize vehicle knowledge speculatively.
6. Never perform automatic unsafe writes.
7. Transport, protocol, knowledge, and UI remain separated.
8. Every physical milestone gets a reproducible fixture or test.
9. Agents must not redesign architecture silently.
10. Create an ADR before changing architecture.
11. Do not build mobile and desktop implementations twice.
12. Add an abstraction only for at least two real consumers or when a hard boundary requires it.
